# Мануал: geeklinker-fallback (аварийный AI-контур)

Человекочитаемая инструкция по использованию. Для самого Claude при
выполнении — см. `SKILL.md` в этой же папке.

## Что это

Третий, резервный способ обработки источников GeekLinker — на случай, когда
и основной скрипт (GCP), и Make одновременно не справляются по общей причине
(например, был реальный случай 2026-09-28: глобальная перегрузка самой
модели Gemini, из-за которой упали сразу оба обработчика на нескольких
источниках). Вместо вызова Gemini API статьи из HTML читает и размечает сам
Claude.

## Как назначить источник на этот контур

В листе `blog_config` в колонке **«Обработчик»** поставьте значение
**`claude`** (так же, как `gc` или `make`). Skill обрабатывает только
источники с этим значением — остальные не трогает, даже если с ними что-то
не так.

Чтобы вернуть источник на обычную обработку — просто поменяйте значение
обратно на `gc` или `make`.

## Как запустить

Работает по расписанию (ежедневно в 00:15 — см. «Статус автоматизации»
ниже), но можно запустить и по запросу в любой момент:

Откройте сессию Claude Code в проекте `geeklinker_bot` и попросите запустить
skill — естественным языком («запусти geeklinker-fallback», «проверь
источники claude-обработчика на новые статьи») или слэш-командой:

```
/geeklinker-fallback
```

Если skill был добавлен/изменён в текущей сессии и слэш-команда не находится
- откройте новую сессию Claude Code в этом проекте, project-level skills
подхватываются при старте сессии.

## Что skill делает

1. Смотрит в `blog_config` активные источники с `Обработчик = claude`.
2. Для rss-источников — обычный парсинг фида (без ИИ).
3. Для scrape-источников — сам Claude читает скачанную страницу и находит
   статьи (замена Gemini на этом шаге).
4. Сверяет найденное с листом `_Dedup` — берёт только то, чего там ещё нет.
5. Добавляет новые статьи в `_Dedup` и в целевой лист (в том же формате
   `HYPERLINK`, что и основной скрипт), сортирует целевой лист по дате,
   шлёт уведомление в Telegram через GeekLinkerBot — как обычная новая
   статья.
6. **Ошибки обрабатывает по тому же правилу, что и основной скрипт:**
   - Сетевые/HTTP-ошибки (таймаут, 403/429/5xx и т.п.) по умолчанию
     считаются «не требующими вмешательства» — сами пройдут при следующем
     прогоне, в Telegram не уведомляют, только пишутся в лог.
   - Если та же ошибка у того же источника повторяется у *этого skill'а*
     три прогона подряд — она перестаёт считаться временной и уходит в
     Telegram.
   - Ошибки, которые в принципе не могут «пройти сами» (robots.txt
     запретил доступ, не удалось разобрать структуру страницы) — сразу
     считаются требующими внимания и уходят в Telegram немедленно.
   - Уведомление в Telegram приходит **отдельным сообщением от основного
     скрипта** — свой заголовок («AI-контур (geeklinker-fallback)»), не
     смешивается с уведомлениями скрипта.
7. Пишет одну строку в лист «Логи» по итогам прогона — как основной скрипт
   (новая строка сверху, цвет по статусу), но полностью за один раз (не
   двухфазно, как скрипт — это нужно, чтобы не пересекаться с его
   блокировкой параллельных прогонов). В колонке «Детали ошибок» всегда
   стоит пометка `[Claude AI Skill]` — одна, если прогон прошёл без ошибок,
   или перед текстом ошибок, если они были. По этой пометке строки от
   skill'а легко отличить от строк основного скрипта, и по ней же skill
   находит свои предыдущие прогоны для проверки повторов (пункт выше).

## Чего skill не делает

- Не трогает источники с `Обработчик = gc` или `make` — только `claude`.
- Не участвует в блокировке параллельных прогонов основного скрипта (та
  механика — `acquire_run_lock`/`finish_run_log` в `main.py`) — строку в
  «Логи» пишет одним цельным действием именно поэтому.
- Не заменяет основной скрипт и Make — это подстраховка, а не полноценная
  замена.

## Где смотреть результат

- **Лист «Логи»** — новая строка сверху с пометкой `[Claude AI Skill]` в
  колонке «Детали ошибок». Самый быстрый способ увидеть, что и когда
  сделал именно этот контур, вперемешку с записями основного скрипта.
- **Telegram (GeekLinkerBot)** — уведомления о каждой добавленной статье (в
  том же формате, что и от основного скрипта) и отдельное сообщение об
  ошибках, если они были.
- **Целевые листы таблицы** — новые статьи появятся там же, где и обычно.
- Итоговая сводка (сколько источников проверено, сколько статей добавлено)
  печатается Claude в чат сессии сразу после выполнения.

## Статус автоматизации (на 2026-09-30)

**Настроено и включено.** Задача Планировщика заданий Windows
`GeekLinker-AI-Fallback` запускает `run_scheduled.bat` ежедневно в **00:15**.
Скрипт вызывает `claude -p` в неинтерактивном режиме
(`--permission-mode bypassPermissions`, инструменты ограничены
`Bash,Read,Write,Edit,Glob,Grep`) с промптом "выполни skill до конца".
Вывод каждого запуска дописывается в `run_log.txt` рядом с этим файлом.

Выбран локальный вариант (Планировщик Windows), а не облачный routine -
главная причина: `sa-key.json` и токен Telegram-бота нужны локально, а
облачный routine не может их безопасно получить без коммита в репозиторий.
Основной риск этого выбора: задача не выполнится, если компьютер в момент
00:15 выключен или спит (см. обсуждение рисков).

**Включить/выключить одной командой** (PowerShell):

```powershell
Disable-ScheduledTask -TaskName "GeekLinker-AI-Fallback"   # выключить
Enable-ScheduledTask  -TaskName "GeekLinker-AI-Fallback"   # включить обратно
```

Проверить текущее состояние и время следующего запуска:

```powershell
Get-ScheduledTask -TaskName "GeekLinker-AI-Fallback" | Get-ScheduledTaskInfo
```

Запустить прямо сейчас, не дожидаясь 00:15 (для проверки):

```powershell
Start-ScheduledTask -TaskName "GeekLinker-AI-Fallback"
```
До тех пор запуск только по запросу, как описано выше.
