# GeekLinker - аварийный AI-контур

Этот skill - третий, независимый от Gemini API способ проверить источники
GeekLinker на новые статьи. Он не заменяет основной скрипт (GCP) и Make, а
подстраховывает их для конкретных, явно назначенных источников: реально нужен
только тогда, когда они оба не справились (например, во время сбоя самой
модели Gemini, как это уже было 2026-09-28 одновременно на Englishdom ru/ua и
Научпоп).

**Область действия — только источники с `engine == "claude"`.** Источник
попадает под обработку этим skill'ом только если в колонке "Обработчик"
листа `blog_config` явно стоит `claude` (как и `gc`/`make`, это ручной выбор
пользователя, а не автоматика). Источники с `gc`/`make` этот skill не трогает
вообще, даже если с ними что-то не так - это не его ответственность.

Рабочая директория для всех команд: `geeklinker_bot/` (там лежат `sa-key.json`,
`.env` и все переиспользуемые модули). Перед первой командой в сессии:

```
cd geeklinker_bot
```

Инструменты этого skill - `helpers.py` в этой же папке, CLI поверх
существующих модулей проекта (`config.py`, `sheets.py`, `feeds.py`,
`notify.py`, `rss_discovery.py`). Он же сам проверяет robots.txt на каждом
шаге, где это уместно - отдельно это делать не нужно.

**Важно:** вывод всех команд `helpers.py` всегда перенаправляй в файл и читай
файл через Read, а не читай stdout напрямую из Bash - в этом окружении
возможны проблемы с кодировкой кириллицы при прямом выводе в консоль.

**Обо всех ошибках выполнения — уведомлять в Telegram** (см. шаг 5): заводи
список строк-ошибок с самого начала прогона и дописывай в него любую
проблему, которая мешает обработать источник или статью (сетевая ошибка,
HTTP-ошибка, robots.txt запретил доступ, не удалось распознать структуру
страницы и т.п.). В конце обязательно отправь их все в Telegram через
`notify_errors`, даже если пользователю об этом отдельно не пишешь.

## Шаг 1. Получить список источников

```
python .claude/skills/geeklinker-fallback/helpers.py list_sources > /tmp/sources.json
```

(используй свою scratchpad-директорию вместо `/tmp`). Прочитай файл. Список
уже отфильтрован: только активные источники с `engine == "claude"`, без
`!blocked`. Если список пуст - значит, ни один источник сейчас не назначен
на этот контур; сообщи об этом пользователю и завершай работу, ошибкой это
не считается.

Каждый источник - `{site_name, url, source_type, target_sheet, engine}`.

## Шаг 2. Для каждого источника получить статьи

**Если `source_type == "rss"`:**

```
python .claude/skills/geeklinker-fallback/helpers.py fetch_rss "<url>" > /tmp/rss_<n>.json
```

Это чистый парсинг RSS (feedparser), Gemini не участвует и тут не нужен -
просто прочитай результат: список `{link, title, pub_date}` уже готов. Если
в файле оказалось `{"error": ...}` (например, robots.txt запретил доступ) -
добавь это сообщение в список ошибок для шага 5 и переходи к следующему
источнику.

**Если `source_type == "scrape"`:**

```
python .claude/skills/geeklinker-fallback/helpers.py fetch_scrape_html "<url>" /tmp/page_<n>.html
```

Аналогично проверь на `{"error": ...}` - если есть, тоже в список ошибок и
дальше. Иначе прочитай сохранённый HTML через Read (или Grep, если файл
большой - сначала поищи повторяющийся паттерн карточки статьи, как в
реальных примерах ниже, и прочитай только релевantные куски). Определи
список статей на странице **сам, своим чтением** - именно это заменяет
Gemini. Для каждой статьи нужны: точная ссылка (полный url), заголовок,
дата публикации.

Подсказки по структуре (могут отличаться на других сайтах - смотри по факту):
- Englishdom: `<div class="blog-item ...">...data-date="YYYY-MM-DD HH:MM:SS"...
  <a href="/blog/<slug>/" title="Заголовок">` (для `/ua/blog/` - href с
  префиксом `/ua/blog/`).
- imena.ua: `<article id="post-...">...<h2 class="entry-title"><a
  href="URL">Заголовок</a></h2>...<time datetime="YYYY-MM-DD HH:MM:SS">`.

Если структура источника незнакома - просто прочитай HTML вдумчиво и найди
список статей визуально (заголовки, ссылки, даты рядом) так же, как делал бы
человек, просматривающий страницу. Если распознать список статей не
получилось вовсе - это тоже ошибка для шага 5 ("не удалось разобрать
структуру страницы <url>"), не придумывай статьи наугад.

Дату приводи к формату `ДД.ММ.ГГГГ` (как everywhere в проекте).

**Прочие типы** (тип не указан/не распознан) - пропускай молча: это резервный
контур, автоопределение типа - забота основного скрипта, и это не ошибка.

## Шаг 3. Проверить, что реально ново

Собери все url со всех источников в один JSON-список и выполни:

```
python .claude/skills/geeklinker-fallback/helpers.py check_dedup /tmp/all_urls.json > /tmp/new_urls.json
```

Это вернёт только те url, которых ещё нет в `_Dedup` - то есть настоящие
кандидаты в новые статьи. Если список пуст - на этом источнике всё уже
обработано, отчитайся и переходи к следующему.

## Шаг 4. Добавить новые статьи

Для каждой по-настоящему новой статьи (только из списка `new_urls.json`,
сопоставленного обратно с её title/pub_date/site_name/target_sheet):

```
python .claude/skills/geeklinker-fallback/helpers.py add_article "<site_name>" "<target_sheet>" "<url>" "<title>" "<ДД.ММ.ГГГГ>"
```

Эта команда сама: пишет в `_Dedup`, добавляет в целевой лист (через формулу
`HYPERLINK`, как основной скрипт), сортирует целевой лист по дате,
отправляет уведомление в Telegram. Если статья внезапно уже оказалась в
`_Dedup` к этому моменту (гонка/повтор) - команда тихо пропустит её и
сообщит об этом, ничего не сломав (это не ошибка).

**Этот skill намеренно НЕ пишет в лист "Логи"** - та механика завязана на
блокировку параллельных прогонов основного скрипта (`acquire_run_lock`/
`finish_run_log` в `main.py`), и вмешиваться в неё отсюда не нужно.

## Шаг 5. Уведомить об ошибках и подвести итог

Если за время прогона накопился список ошибок (шаг 2 - недоступные
источники, шаг 4 и т.п.) - отправь их все ОДНИМ сообщением в Telegram:

```
python .claude/skills/geeklinker-fallback/helpers.py notify_errors /tmp/errors.json
```

где `errors.json` - JSON-список строк с описанием каждой ошибки (включай
название источника/url, чтобы было понятно, о чём речь). Если ошибок не
было - эту команду можно не вызывать вовсе (или вызвать с пустым списком,
она сама ничего не отправит).

В конце — коротко перечисли пользователю в чате: сколько источников
проверено, сколько статей было реально новых и добавлено (с названиями), и
сколько ошибок встретилось и были ли они отправлены в Telegram.
